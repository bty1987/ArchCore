## 3. 技术决策档案（决策 → 选项 → 结果）

### D-A：微信客户端版本——冻结 4.1.8.67

- 选项：留 4.1.15.13（最新）/ 降级 4.1.8.67（Msky 生态锚点）/ 3.9.x（WCFerry 路线）
- 实测：3.9.12.56 与 3.9.5.81 登录均被服务端拒（伪装 3.9.10.19 / 3.9.12.51 / 4.1.15.13 三档均无效——**服务端做协议指纹校验，非仅版本号**）；4.1.8.67 登录成功
- 结果：**冻结 4.1.8.67**。理由：Msky 全家桶（libencode/pywxauto）统一锚点 + 解密管线零适配验证。4.1.15.13 的唯一优势（版本新）被「UIA 地基被拆 + 第三方框架未跟」抵消
- 遗留：升级回 4.1.15 随时可做（解密管线两侧均已验证），由 libencode 支持情况决定

### 5.2 关键实测证据（防遗忘）

- **3.9 登录**：版本伪装三档（3.9.10.19/3.9.12.51/4.1.15.13）全拒——服务端协议指纹校验，伪装无效；
- **4.1 系登录**：4.1.8.67 与 4.1.15.13 均成功——**拒登是 3.9 整代淘汰，非小版本清算**；
- **4.1.15.13 UIA**：登录窗口 `mmui::LoginWindow` 有树；登录后主窗口 `Qt51514QWindowIcon` + `MMUIRenderSubWindowHW` 自绘、**UIA 子树为空**；
- **4.1.8.67 UIA**：需讲述人（Narrator）在登录前启动，树完整、类名 `mmui::MainWindow`（pywechat/pywxauto 均依赖此）；
- **libencode 密钥模型**：通用 passphrase（内存 XOR DLL 内部密钥）+ 每库 salt 派生（PBKDF2-SHA512/256000）；
- **wxhook Account.dbKey**：登录即得 3.x 库密钥（3.x 路线可省取钥步骤）。

### 5.3 分发模式观察（获取渠道）

- Msky 全家桶：文档站公开 + PyPI（pywxauto 已上、libencode 未上）+ **QQ 群私有分发**（wxhook 705791428）——持续跟踪 PyPI；
- tom-snow 仓库：仅 3.x 归档；**4.x 归档在 SiverKing/wechat4.0-windows-versions**（75 个 release，含 4.1.15.13）；
- rpachat：token 发卡站，但 PadLocal 网关已死——购买前必问网关地址。

## 7. 方法论沉淀（可复用经验）

1. **被动优先**：能让微信写盘的（解密轨）绝不做注入的（Hook/协议）——风控档位差两个量级；
2. **合成自测先行**：密码学实现先用合成数据验证数学正确性，再上真机——decrypt_wechat4 的合成自测避免了真机盲调；
3. **失败也要留痕**：计划任务/同步的每次失败都上报心跳——「静默失败」是数据管道的头号杀手（15:53 事故教训）；
4. **自动化验收 = 真实触发一次成功**：配置了计划任务不等于计划任务能用（编码崩溃教训）；
5. **生态结论必须实测**：文档列表滞后（libencode 支持最新版但文档没更新）、域名会死（PadLocal）、群里没包——每个结论都花一次实测确认；
6. **版本冻结 + 锚点选择**：跟随「生态锚点版本」（Msky 全家桶锚 4.1.8.67）而非最新版——生态工具的兼容上限就是你的天花板；
7. **UIA 生死判据**：控件树可见性（讲述人先行是开关、自绘表面是死刑）——一条探测脚本即可判断任何 UIA 工具的真假兼容。
