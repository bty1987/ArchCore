## 1. 定位与前提

本方案将 PRD F8（发起对话）从「一句默认关闭」扩展为**完整的外发风控方案**。前提不变：

> 归档系统「只收不发」天然安全；开放发送是全系统风险等级的一次跃迁。因此发送不作为自由功能开放，而是做成**工单管道 + 规则引擎 + 熔断器**——每一条外发消息都是受约束的、可审计的、可一键停止的工单，不存在任何"直接发送"入口。

产品口径继续遵守场景文档边界：**系统负责理解、整理、分析和辅助；对外沟通由人负责确认。** 本方案的全部设计都是这句话的工程化。

**v0.2 评审补充——先回答「是否做」，再谈「怎么做」**：

- **身份错位**：外发发送者是采集号，客户认知的沟通对象是员工个人。长期沉默的档案号突然发言，社交上突兀，且直接向客户暴露采集存在——此风险无法靠频控消除，只能以「群内公开身份的客服号」缓解；
- **增量价值有限**：采集号上手工外发的消息本就会被自动归档，审计/留痕价值天然存在；本管道的净增量仅是「不碰手机远程发送」的便利，代价是全系统风险等级的一次跃迁；
- **决策默认值**：**永久「只收不发」是本方案的默认终态**。以下全部管道设计视为「若商业化评审推翻默认值时的实施预案」——每一级开放都需要重新论证，不开放不需要理由。

## 2. 风险模型

外发行为触发微信风控的四个信号维度，约束规则全部围绕它们设计：

| 维度 | 高危特征 | 本方案的对策 |
|---|---|---|
| 频率 | 高频、脉冲式、整点批量 | 账号/群/客户三级日预算 + 节奏队列打散 |
| 对象 | 陌生人、非会话关系 | 客户库白名单硬约束（代码级，不可配置绕过） |
| 内容 | 同质内容多对象、营销词、链接二维码 | 内容指纹去重 + 模板审批制 + 禁词表 |
| 时间 | 夜间、节假日、非工作时段 | 时间窗强制 |

三类后果按严重度排序：**账号风险**（封号 = 数据源中断，最重）、**业务风险**（打扰客户引发投诉）、**合规风险**（营销骚扰）。方案优先级：保账号 > 保客户体验 > 保发送效率。

## 3. 行为分级（风险阶梯）

开放顺序按此阶梯逐级评估，**禁止跨级开放**：

| 等级 | 行为 | 风险 | 确认要求 | 默认状态 |
|---|---|---|---|---|
| L0 | 群内回复：回应客户在已映射群里的消息 | 最低（会话已存在，语境自然） | 发起人确认 | 最先开放 |
| L1 | 群内主动消息：向已有客户群主动发跟进/节点通知 | 低 | 发起人 + 主管审批 | L0 平稳后 |
| L2 | 单聊回复：回复已挂靠联系人的私聊（前提：该单聊发生在采集号自身会话，见 PRD 3.1） | 中低 | 发起人确认 | 评估后 |
| L3 | 单聊主动触达：向已有联系人主动发起（同 L2 前提） | 中 | 发起人 + 主管审批 + 留痕理由 | 默认关闭 |
| — | 任何非客户库对象、相同内容多对象、定时批量、朋友圈 | **禁止** | 系统无此入口 | 永久禁止 |

## 4. 行为约束规则体系

### 4.1 红线规则（代码强制，不可配置、不可绕过）

1. **白名单**：只允许发往已映射客户的群/已挂靠联系人，客户库之外的 wxid 在 schema 层即被拒绝；
2. **人工确认**：每条消息必须对应一个由真人创建并确认的发送工单，系统无任何自动发起路径（预警、AI、定时任务均只能生成草稿，不能生成工单）；
3. **内容去重**：相同内容指纹 24 小时内不得发往第 2 个对象（群发特征一票拒绝）；
4. **全局熔断开关**：管理员一键停止全部外发，生效时间 < 10 秒；
5. **异常自动熔断**：见 4.4；
6. **全量审计**：工单创建/审批/派发/回执全链路留痕；系统侧做到 API 无删除入口 + 触发器级防删（部署形态下 admin 可直连 SQLite 文件，文件级访问不在系统控制范围，不承诺绝对不可删除）。

### 4.2 频控与节奏规则（规则引擎，默认保守值，可按客户收紧、不可放宽超过上限）

| 规则 | 默认值 | 说明 |
|---|---|---|
| 账号日预算 | 20 条/天/采集号 | 所有群+单聊合计 |
| 单群日上限 | 3 条/天 | 含 L0 回复 |
| 单客户日上限 | 2 条/天 | 跨该客户所有群 |
| 时间窗 | 工作日 9:00–18:00 | 夜间/周末/节假日禁止；紧急事项走人工手机 |
| 派发节奏 | 队列内分钟级随机间隔 | 工单排队后按正常商务节奏逐条派发，不做整点/集中派发 |

### 4.3 内容规则

- **模板优先**：外发内容从模板库选择（模板需主管审批后入库）；自由输入需填申请理由；
- **禁词表**：营销类词汇（优惠/促销/限时/免费领/点击链接/加微信 等）命中即拒绝提交；
- **附件限制**：默认只允许文件（合同/报价单类业务文档）；链接、二维码、小程序默认禁止；
- **冷却规则**：客户回复命中负面词（不用了/别发了/退订/投诉类）→ 自动冻结该客户外发 14 天 + 通知负责人；客户在群内明示不需要推送 → 人工标记永久冷却。

### 4.4 自动熔断（系统自我监测）

采集端本来就在收消息——这让系统可以**自我感知风控信号**，这是本方案最有价值的安全设计：

| 触发信号（从采集消息流中检测） | 动作 |
|---|---|
| 采集号收到「微信团队」异常登录/环境异常提醒 | 自动全局熔断 + 红警管理员 |
| 发送失败率 1 小时内 > 30% | 自动暂停派发队列，人工排查后恢复 |
| 当日被冷却客户数 ≥ 3 | 暂停全部 L1/L3 主动类工单，仅保留 L0 回复 |
| 采集心跳异常期间 | 派发队列自动挂起（采集不正常时不外发） |

## 5. 技术实现：发送工单管道

```
web 管理台                          server                           collector
──────────                        ──────────                       ──────────
销售发起草稿 ──▶ [规则引擎前置校验] ──▶ SendOrder 工单状态机
                    │ 红线/频控/内容       draft → pending_approval
                    ▼ 拒绝并说明原因       → approved(主管审批)
              (L1/L3 需审批)              → queued(节奏队列, 分钟级打散)
                                              │ 逐条派发
                                              ▼ wcf_worker 拉取工单
                                          [执行端无决策权：只执行
                                           已批准工单，无自主发送]
                                              │ 回执
  管理台外发看板 ◀── 全量审计留痕 ◀── 状态回写 delivered/failed/cancelled
        ▲
  熔断器（全局开关 / 自动熔断信号 / 队列挂起）
```

设计要点：

- **决策权与执行权分离**：全部策略集中在 server（规则校验、频控计数、节奏队列、熔断器）；collector 的发送通道只负责执行已批准工单——即使采集端配置泄露，拿到的也只是"拉取工单"的能力，无法批量自主发送；
- **工单状态机可追溯**：谁起草、谁批准、何时派发、结果如何，一条记录闭环；
- **模块物理隔离**：发送管道为独立模块（`server/services/outbound.py` + `collector/wcf_worker/sender.py`），配置开关 `send_enabled` 默认 `false`；关闭状态下相关路由不注册、队列不启动——不发送时系统攻击面与纯归档版完全相同；
- **频控计数器**：账号/群/客户三级计数落库，跨重启有效。

## 6. 治理与运营

| 项 | 安排 |
|---|---|
| 角色权限 | 发起（销售）、审批（主管）、开关与审计（管理员）三级分权；发起人不能审批自己的工单 |
| 外发看板 | 日/周外发量、成功率、审批通过率、冷却客户数、熔断次数——熔断次数 > 0 即需复盘 |
| 效果回看 | 每月复盘：外发后客户负面率、响应率；负面率高的模板下架 |
| 客户知情 | 交付培训中向客户方明确外发规则与「说不」机制（冷却规则即客户的拒绝通道） |
| 定期审计 | 每季度抽查工单样本（内容合规性、审批完整性）；红线规则代码评审纳入迭代 |

## 7. 灰度路径

1. **默认关闭**（MVP/V1 全程）：只建管道不启用；
2. **内部试点开放 L0**（V1 后）：自己公司真实使用 ≥ 2 周，观察熔断计数、失败率、客户负面反馈；
3. **逐级评估开放**：L0 → L1 → L2，每级观察 ≥ 2 周且指标达标（零投诉、失败率 < 5%）再升一级；
4. **L3 与一切"禁止"级**：无开放时间表，每次商业化评审重新论证；
5. **任一客户出现封号**：该客户环境立即回退到纯归档模式，全局复盘后才可再评估。

## 8. 与现有文档的关系

- PRD F8 由「默认关闭的可选项」升级为「按本方案灰度实施」，排期仍维持 V2（预警与分析优先）；
- 系统设计 D6（发送能力独立模块 + 默认关闭）由本方案第 5 节具体化；
- 运维规划 2.7 账号资产台账增加字段：外发预算使用量、最近熔断时间；Runbook 增加一行：外发失败率告警 → 检查工单队列与登录状态。
