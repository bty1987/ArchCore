# Customer OS 技术架构与开发路线

## 1. 总体架构

```text
                 Web / Mobile
                      │
                 API Gateway
                      │
              ┌───────┴────────┐
              │                │
         Core Service       AI Service
              │                │
       ┌──────┼───────┐        │
       ↓      ↓       ↓        ↓
   Contact  Inbox  Workflow  LLM Gateway
       │      │       │        │
       └──────┼───────┘        │
              ↓                ↓
          Event Bus       Knowledge Base
              │
      ┌───────┼───────────┐
      ↓       ↓           ↓
    WeCom  WhatsApp    WebChat
      ↓       ↓           ↓
   Channel Adapter Layer
```

---

# 2. 多租户

所有核心表：

```text
workspace_id
```

作为租户隔离字段。

建议：

- PostgreSQL
- Row-level application isolation
- Tenant-aware cache key
- Tenant-aware object storage

---

# 3. Channel Adapter

必须定义统一模型：

```java
Channel
Conversation
Participant
Message
Attachment
DeliveryReceipt
WebhookEvent
```

业务层绝不能出现：

```java
if (wechat) ...
if (whatsapp) ...
```

所有差异放在 Adapter。

---

# 4. 个人微信策略

个人微信属于高风险 Connector。

不要把：

```text
PadLocal
wxauto
Hook
Paimon
```

写死进 Core。

采用：

```text
PersonalWeChatAdapter
        │
 ┌──────┼────────┐
 ↓      ↓        ↓
wxauto  Hook   Paimon
```

这样第三方方案失效时不会影响 CRM 核心。

---

# 5. 企业微信策略

企业微信优先采用官方能力。

原则：

> 官方 API > 官方应用/客服能力 > 合规第三方服务 > UI 自动化 > 协议逆向

---

# 6. AI Gateway

不要把业务代码直接绑定某一家 LLM。

统一：

```java
interface LlmProvider {

    ChatResponse chat(ChatRequest request);

    EmbeddingResponse embedding(EmbeddingRequest request);
}
```

实现：

```text
OpenAI
Anthropic
Google
DeepSeek
Qwen
Local
```

---

# 7. Workflow Engine

第一版不要引入非常复杂的 BPM。

采用：

```json
{
  "trigger": "message.received",
  "conditions": [],
  "actions": [
    {
      "type": "add_tag",
      "tag": "new_lead"
    },
    {
      "type": "assign_user",
      "user_id": "..."
    }
  ]
}
```

未来再演化成 DAG。

---

# 8. Event Model

所有重要动作产生事件：

```text
contact.created
contact.updated
message.received
message.sent
conversation.opened
conversation.closed
tag.added
workflow.started
workflow.completed
ai.completed
deal.created
deal.won
```

事件是后续 AI、BI、Automation 的基础。

# 10. 推荐技术栈

如果沿用 Java：

```text
Backend:
Java 21
Spring Boot 3.x
Spring Security
PostgreSQL
Redis
Kafka/RabbitMQ

Frontend:
React
TypeScript
Ant Design

Workflow:
自研轻量 Workflow Engine

AI:
统一 LLM Gateway

Storage:
S3-compatible Object Storage

Search:
PostgreSQL → OpenSearch

Deployment:
Docker
Kubernetes（规模后）
```

不建议 MVP 直接微服务。

推荐：

> **Modular Monolith + Event Driven**

等到：

- AI
- Workflow
- Channel
- Billing

出现独立扩展压力后再拆服务。

# 12. 核心架构原则

1. Channel-independent
2. Tenant-first
3. Event-first
4. API-first
5. AI as capability
6. Workflow as capability
7. Human-in-the-loop
8. Connector isolation
9. Modular monolith first
10. Security by default
