## 1. 文档定位

回答一个问题：**ArchCore 现在离「可以推广的产品」有多远，差什么，按什么顺序补。**

两条边界：

- **推广策略不重新设计**——口碑主线（[运维与推广规划](ops-promotion-plan.md)三阶段）+ 自媒体第二发动机（[自媒体推广作战包](自媒体推广作战包.md)，2026-10-01 定案）均已成立，本文只做确认与执行排序；
- **本文聚焦功能之外的差距**——可安装性、支撑体系、合规法律、售前材料四层，这些决定了「代码全绿」和「敢收客户钱」之间的距离。

所有结论基于 2026-10-04 的代码与文档实盘（server/web/collector 全量盘点 + docs 文档链通读）。

- **2026-10-15 新增**：AI 经营周报（每周一自动生成推送）、AI 助手（自然语言查数据）、管道仪表（采集成功率/耗时/每日消息量）、管理台「暖纸账本」全新 UI；

**交付层（2026-10-15 补齐）**：`install.bat` 一键安装（venv+依赖+配置生成+迁移+前端构建）、`run-demo.bat` 演示模式（隔离库 + 四类预警场景）、首启强制改密、README 系统预览画廊（五图）。

## 3. 推广路径确认与执行顺序

推广已定案为**双发动机并行**：

- **口碑线（主线）**：三阶段路径——内部试点 → 种子客户 → 转介绍，阶段 1 案例质量重于客户数量；
- **自媒体线（第二发动机）**：公域讲痛点建信任、交付全进私域（公域不卖、不教安装，五条公开红线见作战包 §一），**60 天可证伪门槛**——私域免费评估请求 ≥5 个且 ≥1 个进演示才放量，否则降速为案例存档号、主力回口碑线，不恋战。

执行排序：

1. **现在起，收尾阶段 0**：内部连续使用满 1 个月（退出标准：预警处理率 >50%），同步积累脱敏案例素材（截图 + 效率数据，如「每周节省 X 小时翻记录」「抓住 Y 次响应超时」）；自媒体线攒号期与试点期重叠，W1 起按作战包节奏出内容；
2. **并行补齐 P0 缺口**（见 §6：文档类模板定稿 + 开发类 3 项）——未补齐前不接触第一家外部客户；
3. **遴选 3~5 家关系老客户**（不同行业、有基础 IT 条件）免费/成本价试点，签试点协议，换三样东西：真实环境反馈、可对外引用的案例授权、转介绍承诺；
4. **商业化阶段才定正式定价**；ops-promotion-plan 3.4 的定价建议（部署费 + 年费，按管理用户数 + 归档群数阶梯）够作内部测算基础。

Customer OS 融合路径决策（路径 2 WebChat demo → 路径 1 多租户，见衔接分析 §7）**不阻塞内网版推广**；推广期应有意识记录客户对 SaaS 化 / WebChat 的诉求，作为该决策的输入。

## 4. 差距分析（四层，按严重度）

### A. 可安装性 / 交付力 —— 已基本补齐（2026-10-15）

最小改造清单进展：

1. ✅ **一键安装脚本**（`install.bat`，七步固化；含配置生成器 `scripts/install_config.py`，已存在文件一律保留）；
2. ✅ **首启强制改密**（默认密码登录即强制跳改密页；`POST /auth/change-password`）；
3. ✅ **演示模式**（`run-demo.bat`：隔离库 + 120 天合成数据 + 四类预警场景 + 自动开浏览器）；
4. ❌ **版本接口 + 升级脚本**（客户部署后的更新通道）——**唯一未做的开发项，估 1~2 天**；
5. 授权/许可机制**暂缓**——种子期靠协议约束，转介绍模式下复制风险低。

### B. 稳定性与支撑体系 —— **当前主卡点**（2026-10-15）

运维文档很全（版本冻结、账号台账、Runbook、备份）。备份恢复已于 2026-10-25 实走通过；「没演练过的预案不是预案」原则不变，剩余项照此推进：

- ✅ **一次真实备份恢复演练已完成（2026-10-25）**——在线备份/完整性校验/独立目录恢复/数据零差异/FTS 链路验证全过，实际耗时约 2 分钟；记录见 [deploy/演练记录-备份恢复-20261025.md](../deploy/演练记录-备份恢复-20261025.md)；
- 换号 SOP 从桌面推演走到实跑（或至少完整走通备用号配置切换）；
- 采集可用率有 1 个月实测数据（对客承诺 >99% 需先自证）。

> 开发类缺口已补齐（§4-A），**这一层成为唯一挡在「接触第一家客户」前的硬缺口**。

### C. 合规与法律文件 —— 正式商用的前置闸门

compliance-plan 停在 v0.1，所列评估项（第三方个人信息告知、数据最小化、权限收敛）未执行；合同侧的试点协议、免责条款、数据归属条款在多处文档被引用却**没有实际模板文件**。这层不补，接触外部客户等于裸奔——尤其采集路线的封号风险与第三方个人信息问题必须合同化。

### D. 售前与市场材料 —— 模板已建，待演练定稿（2026-10-15）

ops-promotion-plan 3.2 的材料清单已按 2026-10-01 产出模板（一页纸/演示脚本/FAQ/定价表，见 docs/售前工具箱/）。答案素材都在（场景文档的话术、运维文档的 FAQ 答案），演示环境也已就绪（`run-demo.bat`）——缺的是**按假想客户走一遍、把模板练成成稿**；案例素材待阶段 0 积累。

## 5. 对外口径修正（两处已过时）

1. **AI 摘要/标签已上线**：ops-promotion-plan 3.2 与 product-scenarios 交付边界说明中「AI 摘要属 V2+ 规划、不得作为卖点」的表述**已过时**——AI 摘要/标签实际已随当前版本上线，应放入当期承诺，且是当前最强差异化卖点（竞品做不了个人微信存量归档 + AI 整理，见衔接分析 §6）；
2. **实时轨表述**：PadLocal 官方网关已死（复盘档案 §5），对外统一口径为「**增量同步（30 分钟级）+ 可选实时增强**」，不做秒级实时承诺。
