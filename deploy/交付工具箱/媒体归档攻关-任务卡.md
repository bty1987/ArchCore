# 媒体本体归档攻关 · 任务卡

> 建立：2026-10-01 ｜ 优先级：P1（商业化价值大项）｜ 状态：待启动
> 背景：文本层全链路已闭环（9-26 复盘），但图片/文件/视频/语音的**本体**未归档——客户感知价值的大头（报价单、图纸、合同照片）在这里。PRD 现状=存元数据+按保留策略处理，本体归档是遗留项（复盘档案 §8）。

---

## 一、目标（Definition of Done）

白名单群内的图片/文件/视频消息，其本体文件从微信数据目录安全落库到 `media/`，满足：

1. 检索命中消息时可直接打开本体（管理台内预览或打开文件）；
2. 落库过程**零注入、零主动调用微信进程**（与解密主轨同一风控档位：被动读盘）；
3. 失败可重试、有心跳上报（"静默失败"禁令同样适用）；
4. 受白名单（F1-6）与保留策略约束，不扩大采集范围。

## 二、三条技术路线（按序试验，前败再进）

| # | 路线 | 原理 | 预估 | 风险 |
|---|---|---|---|---|
| R1 | **libencode CDN API 捷径**（复盘档案点名） | 若 libencode 提供媒体下载接口，用其拉取 CDN 资源后落库 | 0.5–1 天 | 依赖 ¥800 采购 + 包获取；API 覆盖面未知 |
| R2 | **自研媒体密钥** | 沿用自研解密管线经验：找 4.x 媒体文件加密密钥（dat/xdat 头解析或内存密钥），离线解密落盘 | 2–5 天（不确定性最大） | 4.1.8.67 已冻结=目标版本固定，攻关成本一次性 |
| R3 | **元数据+半自动过渡**（零攻关兜底） | 本体留在微信目录+定期整目录备份映射；管理台提供"在微信中查看"跳转与目录索引 | 0.5 天 | 体验打折，但客户价值立即可交付 |

**决策规则**：libencode 到货当日先验 R1；R1 覆盖不全或未到货→R2 立项（时间盒 5 天，超时降 R3 上线，R2 转长期）；试点客户催得紧→R3 先行不丢人。

## 三、验收用例（最小集）

- [ ] 白名单群发送图片 → 下一个同步周期内管理台可预览
- [ ] 大文件（≥100MB）与失效 CDN 资源的失败重试与告警
- [ ] 白名单外群的媒体零落库（合规项）
- [ ] media/ 磁盘增长纳入运维日历容量评估（运维规划 2.2）
