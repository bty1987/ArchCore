# ArchCore 管理台重设计 · 设计 spec(三版概念稿唯一共同输入)

## 产品是什么

ArchCore——微信客户智能经营平台(私有化 SCRM 高阶形态)。把散落在个人微信里的客户沟通,变成可检索、可理解、可预警、可分析的企业资产。核心模型:**一个微信群 ≈ 一个客户**。部署形态:跑在用户自己的电脑/内网,数据 100% 自有(SQLite 单文件),系统永久只收不发(理解与沉淀,不是替用户自动聊)。产品口号:"让每一条客户消息,都变成企业可以理解和经营的业务资产。"

## 目标受众与使用场景

使用者=企业老板/经营者本人(可能配一名运营),在 Windows Chrome 上每天打开数次,**1440×900 主视角**。核心诉求:打开 10 秒内看清"生意现在怎么样"——客户状态、今天动静、有没有人需要跟进、系统采集是否健康。长期每天使用,不能腻、不能吵。

## 页面范围与内容(以工作台 Dashboard 为代表页,真实字段,禁止编造新字段)

导航结构(两级分组,现有信息架构,不可改):
- 业务:工作台 / 客户中心 / 消息检索 / 预警中心 / 洞察分析
- 系统:采集与通道 / 系统设置
- 顶部右区:通知、当前用户(bty1987)、退出

工作台内容块(七块,数据为示例值,须在页面注明「示例数据」):
1. **四指标卡**:客户总数 31 · 已映射/待认领会话 27/4 · 今日消息量 148 · 待处理预警 3
2. **近 14 天消息趋势**折线图(日期 09-30~10-13,数值 60~180 间波动,10-12 峰值 176)
3. **Top 5 活跃会话**表:会话名(如「库迪咖啡供应链群」「大美婆」「美团拼好饭群」)、类型(群聊/单聊)、消息量(412/287/233/186/154)
4. **待办中心**:待处理预警 3 · 待认领会话 4 · 洞察分析入口(可点击行)
5. **客户健康度**:红 2 / 黄 5 / 绿 24
6. **采集状态**:最近同步 `WAL 增量 · 成功 · 今天 14:32`;另有一条心跳「系统正常」
7. **消息类型分布**:text 62% / image 15% / voice 8% / appmsg 9% / video 3% / system 3%(横条占比)

## 情感基调与气质关键词

经营资产感、可信、专业、克制。它不是炫酷监控大屏(不是 gráfico),是**生意人的账本与仪表盘**——安静、可靠、经得起每天看。关键词:私有化 / 资产 / 洞察 / 可信 / 克制。

## 视觉母题(从内容长出来的 form 依据)

「**沉下来的消息流变成资产**」——消息是流动的(趋势线/流),沉淀后是账本与档案(表/层级/编号)。每版交付时须写明:form 来自内容的哪里。

## 必含元素与硬约束

- **AI 助手入口**(用户明确认可的设计元素):以对话入口形式出现(浮动按钮或侧栏项),占位即可不实现对话
- 中文排印:引号用「」;正文 ≥14px,标签/注释 ≥12px,正文对比度 ≥4.5:1
- 图标:禁止 emoji 图标;允许内联 SVG 线性图标(单色,克制)
- 禁:紫渐变、圆角卡片+左彩边组合、均匀深蓝底+通用霓虹 glow 的 GitHub 偷懒解
- 图表用内联 SVG/纯 CSS 静态呈现(概念稿无外部 JS 依赖;允许 Google Fonts CDN+系统字体 fallback)
- 无照片素材需求(数据即内容);ArchCore 用**文字标**(现无 logo,不得编造图形 logo)
- 单文件 HTML,1440×900 视角,页面可自然滚动,双击即可打开
